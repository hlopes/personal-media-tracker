# Image-to-Wishlist as sequential agents with Tavily evidence

Replaced the single-call ImageGuessService with a sequential Image-to-Wishlist Workflow (vision extraction agent → text identification agent with a Tavily search tool → Catalog verification → Library Entry lookup with suggest-only Wishlist prompt), because poster OCR and still-scene analysis need different model strengths than title identification, and Tavily is evidence only: a match still requires TMDB resolution to a cached MediaItem before any Wishlist statement, keeping the Catalog the single source of truth. The extraction agent binds to a named vision model on :9001 while identification stays on the text model on :9000; when the Tavily key is absent the tool reports unavailable and the flow degrades to direct-answer plus TMDB verify. Bytes stay in memory and low-confidence results short-circuit before Catalog and library calls.
